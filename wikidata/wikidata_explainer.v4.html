Background

A wordnet groups words into synsets — sets of synonyms that share one meaning. The Czech wordnet is an expand wordnet: it does not invent its own meanings. Each Czech synset is pinned to an ILI (Interlingual Index) id — a language-neutral concept number like i46360 — and borrows its structure from English. Every wordnet that shares an ILI is talking about the same concept.

Wikidata already links many of its items to a wordnet concept, through one of two properties:

  • P5063 “Interlingual Index ID” — the ILI directly (i46360). Fewer items carry it (~20k).
  • P8814 “WordNet 3.1 Synset ID” — a WordNet offset (02086723-n). More items (~35k), but it is not an ILI yet.

The job: take every Wikidata item that has one of these links and a Czech label, find the matching Czech synset, and ask whether the label is already there. Where it is not, we have a candidate to add.

The one hard part. P8814 is a WordNet 3.1 offset. The Czech wordnet is keyed to ILIs. To cross from one to the other we use the Collaborative Interlingual Index table ili-map-pwn31.tab. Mapping through the English wordnet omw-en:2.0 instead would fail — that is WordNet 3.0, whose offsets do not line up with 3.1.

Where the mappings come from

The ILI is the Collaborative Interlingual Index — a shared registry of concepts, seeded from Princeton WordNet 3.0 and maintained by the Global Wordnet Association. It exists so that every wordnet has one common set of concept ids to link to.

The offset → ILI tables live in one place, the globalwordnet/cili repository. ili-map-pwn31.tab is the WordNet 3.1 table this script downloads; older-wn-mappings/ holds 1.5–2.1 for older sense inventories — the Prague Dependency Treebank, in project 3, is tagged against PWN 1.5. Wikidata's P5063 and P8814 values are added by editors and bots; this script takes them as given.

So the script sorts every item into four buckets:

  • present  the label is already a lemma in the synset — nothing to do.
  • missing-lemma  the synset exists, but lacks this label — a candidate synonym to add (Nizozemsko beside Holandsko).
  • missing-synset  no Czech synset for that ILI at all — a candidate new synset.
  • no-ili  could not resolve an ILI (rare).

The two missing-* buckets are the output that matters. A first sweep is full of named entities (Uganda), so the real work — the validation — is deciding which candidates a general wordnet should actually take.

3 · Fetch from Wikidata

wikidata_to_czech.py:37–57

One SPARQL query asks for items that have either property, plus a Czech label. The UNION means an item carrying both P5063 and P8814 comes back as two rows, so the loop folds rows into one record per item (qid), keeping whichever of ili / wn each row supplies.

SELECT ?item ?cs ?ili ?wn WHERE {
  { ?item wdt:P5063 ?ili . } UNION { ?item wdt:P8814 ?wn . }
  ?item rdfs:label ?cs . FILTER(lang(?cs) = "cs")
} LIMIT {limit}

For each item: resolve an ILI — prefer P5063, and only fall back to mapping P8814 through the CILI table. Then look up the Czech synset by ILI and decide the bucket. The or on this line is the whole preference rule:

ili = rec["ili"] or pwn31_to_ili.get(rec["wn"])   # prefer P5063

cs_syns   = cs.synsets(ili=ili)
cs_lemmas = [w.lemma() for s in cs_syns for w in s.words()]
if not cs_syns:            kind = "missing-synset"
elif label in cs_lemmas:   kind = "present"

Appendix — SPARQL in 60 seconds

Never written a query? SPARQL asks a graph database to find patterns. You need only a few ideas to read the one in this script.

Wikidata is triples

Every fact is a triple — a subject, a predicate, an object: Netherlands — instance of — country. A query draws a pattern with blanks (variables, written ?like_this) and asks for every way to fill them in.

Three prefixes to recognise

  • wd: — an entity. wd:Q55 is the Netherlands.
  • wdt: — a property, as a direct claim. wdt:P5063 is “Interlingual Index ID”.
  • rdfs:label — an item's name, in some language.

Our query, read aloud

SELECT ?item ?cs ?ili ?wn WHERE {
  { ?item wdt:P5063 ?ili . } UNION { ?item wdt:P8814 ?wn . }
  ?item rdfs:label ?cs . FILTER(lang(?cs) = "cs")
} LIMIT 500

“Find every ?item that has a P5063 value or a P8814 value — that is what UNION does — and whose label ?cs is in Czech, which FILTER(lang(?cs) = "cs") keeps. Return at most 500 rows.” The SELECT line just lists which blanks to report back; the . ends each triple pattern.

Try it. Paste the query into the Wikidata Query Service and press the play button — it has autocomplete and a results table. Starting from zero? The Wikidata SPARQL tutorial is the place to begin.
