Background

A wordnet groups words into synsets — sets of synonyms that share one meaning. The Czech wordnet is an expand wordnet: it does not invent its own meanings. Each Czech synset is pinned to an ILI (Interlingual Index) id — a language-neutral concept number like i46360 — and borrows its structure from English. Every wordnet that shares an ILI is talking about the same concept.

What that looks like, for four concepts this run touched. The Czech synset reuses the English synset's WordNet 3.0 offset in its id, and both carry the same ILI:

ILIomw-en:2.0 synsetntumc-cs:2026.08 synset
i46360 omw-en-02084071-n dog, domestic dog, Canis familiaris — "a member of the genus Canis … domesticated by man" ntumc-cs-02084071-n pes, psovitá šelma
i78175 omw-en-07813107-n salt, table salt, common salt ntumc-cs-07813107-n sůl, stolní sůl
i83737 omw-en-08949093-n Netherlands, The Netherlands, Holland ntumc-cs-08949093-n Holandsko
i2294 omw-en-00404202-a colorless, colourless ntumc-cs-00404202-a bezbarvý

Wikidata already links many of its items to a wordnet concept, through one of two properties:

  • P5063 “Interlingual Index ID” — the ILI directly (i46360). Fewer items carry it (~20k). Q144 pes domácí has P5063 = i46360; Q5432619 nepravda has only P5063 (i13643).
  • P8814 “WordNet 3.1 Synset ID” — a WordNet offset (02086723-n). More items (~35k), but it is not an ILI yet. Q55 Nizozemsko has only P8814 = 08968866-n; Q1013 Lesotho only 08978603-n.

In this run's 500 rows, 426 of the 466 items came with a P8814 value and 40 with P5063 alone. A second call of the same query a minute later returned 471 items (the result set is not stable between calls): 394 with P8814 only, 65 with P5063 only, 12 with both. In 11 of those 12 the two routes agree — pes domácí: P5063 i46360, and P8814 02086723-n maps to i46360 too. The one disagreement is Q10850 hlodavci "rodents": P5063 says i47793, Rodentia the order (Czech řád Hlodavci, řád Rodentia), while P8814 02332053-n maps to i47794, rodent the animal (Czech hlodavec). The script prefers P5063, so the label is compared with řád Hlodavci and comes out missing-lemma. Which sense is right is a judgement the script does not make.

The job: take every Wikidata item that has one of these links and a Czech label, find the matching Czech synset, and ask whether the label is already there. Where it is not, we have a candidate to add.

The one hard part. P8814 is a WordNet 3.1 offset. The Czech wordnet is keyed to ILIs. To cross from one to the other we use the Collaborative Interlingual Index table ili-map-pwn31.tab. Mapping through the English wordnet omw-en:2.0 instead would fail — that is WordNet 3.0, whose offsets do not line up with 3.1.

How far apart they are, for three items in this run:

Where the mappings come from

The ILI is the Collaborative Interlingual Index — a shared registry of concepts, seeded from Princeton WordNet 3.0 and maintained by the Global Wordnet Association. It exists so that every wordnet has one common set of concept ids to link to.

The offset → ILI tables live in one place, the globalwordnet/cili repository. ili-map-pwn31.tab is the WordNet 3.1 table this script downloads; older-wn-mappings/ holds 1.5–2.1 for older sense inventories — the Prague Dependency Treebank, in project 3, is tagged against PWN 1.5. Wikidata's P5063 and P8814 values are added by editors and bots; this script takes them as given.

The table itself is two tab-separated columns, 117,587 lines, ILI first:

$ head -3 ili-map-pwn31.tab
i1	00001740-a
i2	00002098-a
i3	00002312-a
$ grep -P '\t02086723-n' ili-map-pwn31.tab      # dog
i46360	02086723-n
$ grep -P '\t06629056-n' ili-map-pwn31.tab      # anime (Q1107): no line

Not every 3.1 offset is in it. Q1107 anime carries P8814 06629056-n, a synset added in WordNet 3.1 that never received an ILI (omw-en knows anime only as a resin) — the one no-ili of this run. And 47 offsets appear on two lines (00008423-r is both i18197 and i19554); a dict keeps the later one.

So the script sorts every item into four buckets. The counts are from this run (466 items); the faces beside each are its first members:

  • present  106 — the label is already a lemma in the synset — nothing to do: pondělí, sůl, autobus, mrakodrap "skyscraper", bílé víno.
  • missing-lemma  83 — the synset exists, but lacks this label — a candidate synonym to add: Nizozemsko beside Holandsko, palubní průvodčí beside letuška "stewardess", koncertní sál beside koncertní síň, elektronové dělo beside elektronová tryska "electron gun".
  • missing-synset  276 — no Czech synset for that ILI at all — a candidate new synset: Lesotho, Boston, Mahátma Gándhí, but also milník "milestone", jetel "clover", hlezenní kost "anklebone", labužník "connoisseur".
  • no-ili  1 — could not resolve an ILI: anime (P8814 06629056-n, absent from the CILI table).

The two missing-* buckets are the output that matters, and they are noisier than their names. Of the 276 missing-synset items, 131 are instances in the English wordnet — named entities such as Lesotho, Boston, Bill Clinton, Mars the Roman god — and the lexfiles are led by noun.location (65) and noun.person (59). The other 145 are common nouns a general wordnet might want: plazma, hadron, konfit, iglú, postdoktorand.

The missing-lemma bucket hides a different kind of noise: the test is an exact string match, so a label that differs from an existing lemma only in form is still "missing". Real rows from this run:

So the real work — the validation — is deciding which candidates a general wordnet should actually take, and the four buckets are where that work starts, not where it ends.

3 · Fetch from Wikidata

wikidata_to_czech.py:37–57

One SPARQL query asks for items that have either property, plus a Czech label. The UNION means an item carrying both P5063 and P8814 comes back as two rows, so the loop folds rows into one record per item (qid), keeping whichever of ili / wn each row supplies.

SELECT ?item ?cs ?ili ?wn WHERE {
  { ?item wdt:P5063 ?ili . } UNION { ?item wdt:P8814 ?wn . }
  ?item rdfs:label ?cs . FILTER(lang(?cs) = "cs")
} LIMIT {limit}

What that does to Q144 pes domácí, which has both properties: two bindings arrive, and the loop folds them into one record.

row 1   item=…/entity/Q144  cs="pes domácí"  ili="i46360"
row 2   item=…/entity/Q144  cs="pes domácí"  wn="02086723-n"

items["Q144"] == {"label": "pes domácí", "ili": "i46360", "wn": "02086723-n"}
items["Q55"]  == {"label": "Nizozemsko", "ili": None,     "wn": "08968866-n"}

That folding is why 500 rows became 466 items in this run: an item with both properties, or with two values for one of them, fills more than one row. Note also that nothing here is sorted — Wikidata returns the first 500 matches it finds, which is why the set differs from one call to the next.

4 · Resolve, classify, report

wikidata_to_czech.py:60–94

For each item: resolve an ILI — prefer P5063, and only fall back to mapping P8814 through the CILI table. Then look up the Czech synset by ILI and decide the bucket. The or on this line is the whole preference rule:

ili = rec["ili"] or pwn31_to_ili.get(rec["wn"])   # prefer P5063

cs_syns   = cs.synsets(ili=ili)
cs_lemmas = [w.lemma() for s in cs_syns for w in s.words()]
if not cs_syns:            kind = "missing-synset"
elif label in cs_lemmas:   kind = "present"
else:                      kind = "missing-lemma"

Appendix — SPARQL in 60 seconds

Never written a query? SPARQL asks a graph database to find patterns. You need only a few ideas to read the one in this script.

Wikidata is triples

Every fact is a triple — a subject, a predicate, an object: Netherlands — instance of — country. A query draws a pattern with blanks (variables, written ?like_this) and asks for every way to fill them in.

Three prefixes to recognise

  • wd: — an entity. wd:Q55 is the Netherlands.
  • wdt: — a property, as a direct claim. wdt:P5063 is “Interlingual Index ID”.
  • rdfs:label — an item's name, in some language.

Our query, read aloud

SELECT ?item ?cs ?ili ?wn WHERE {
  { ?item wdt:P5063 ?ili . } UNION { ?item wdt:P8814 ?wn . }
  ?item rdfs:label ?cs . FILTER(lang(?cs) = "cs")
} LIMIT 500

“Find every ?item that has a P5063 value or a P8814 value — that is what UNION does — and whose label ?cs is in Czech, which FILTER(lang(?cs) = "cs") keeps. Return at most 500 rows.” The SELECT line just lists which blanks to report back; the . ends each triple pattern.

Try it. Paste the query into the Wikidata Query Service and press the play button — it has autocomplete and a results table. Starting from zero? The Wikidata SPARQL tutorial is the place to begin.

Glossary

TermWhat it means here
synseta set of synonyms sharing one meaning — the unit a wordnet links. pes and psovitá šelma sit in one synset.
lemmaa word form listed in a synset (Holandsko). A missing-lemma is a lemma to add.
ILIInterlingual Index id (i46360): a language-neutral concept number shared by every wordnet.
expand wordneta wordnet that reuses shared concepts through the ILI instead of defining its own. The Czech wordnet is one.
CILICollaborative Interlingual Index: the registry of ILIs and the PWN → ILI tables in globalwordnet/cili.
P5063 / P8814the two Wikidata properties — the ILI directly, and a WordNet 3.1 offset.
offseta synset's position in a Princeton WordNet release, plus its part of speech. It changes between releases: dog is 02084071-n in 3.0 and 02086723-n in 3.1.
instancea synset for one named thing rather than a kind — Lesotho, Boston, Bill Clinton — linked by instance_hypernym. 131 of this run's 276 missing-synset items are instances.
