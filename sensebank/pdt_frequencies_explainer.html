Background

Between 2004 and 2011, ÚFAL annotated words of the Prague Dependency Treebank (PDT) with synsets of their own copy of the Czech WordNet. The annotation is stand-off: a file per document that says, for each word id, which tag it got. The copy of the wordnet is Czech WordNet 1.9 PDT. All three are on LINDAT under CC BY-NC-SA.

A sense is a word in a synset: slovo in the synset for "word", cenit si "value" in its synset. A count says how often a sense is used in a corpus. The Czech WordNet 2.2 already has counts for 1,736 senses from the NTU-MC Czech corpus; PDT is far larger, so every tag that reaches a sense is a count worth having.

The catch is that the tags name synsets of a different wordnet, by Princeton WordNet 1.5 offsets, while the release counts in 2.0. The bridge is the CILI map from 1.5 offsets to ILIs, and the release synset with the same ILI. Each link in that map has a confidence; the low ones are often wrong: dobrý "good" maps to the concept the release calls výborný "excellent".

A tag is not always a synset. It can be one of the annotators' exceptions (a small number such as 1 or 7, for "missing sense" or "proper name"), or a hyphen for a word the annotators did not agree on.

Intuition

Every annotated word walks down the same chain of tests. The first test it fails decides its fate; a word that passes them all is counted. The numbers are the words with each fate in the full run (report/facts-freq.json), out of 148,865 annotated words.

Two fates are nearly empty. Document not in PDT 3.0 has three words: their document has no morphological file in PDT 3.0, so there is no lemma to match. Tag names no synset has none since the fix described in How much to trust this, but the test stays as a guard.

Why the order matters. The confidence test comes before the release is consulted, so a doubtful link is never counted, even when its word happens to be in the target synset. Counting fewer words is the price of not counting lepší as "excellent".

1 · Settings

Only links of confidence 1 are trusted. FATES lists every fate with the short name the report's facts.tex uses. The rest describes the change records: corpus, source, reason and user.

MIN_CONFIDENCE = 1.0
CORPUS = "PDT"
REASON = "how often the sense is tagged in the corpus"

2 · candidates(): the forms a word may have

pdt_frequencies.py:70–83

PDT lemmatises cenili to cenit (the si is a separate word) and neúspěchy to úspěch (negation is in the tag). The wordnet lists cenit si and neúspěch. So the script tries the bare lemma, both reflexive forms, and, if position 11 of the morphological tag is N, the ne- form.

base = base_lemma(tok.lemma)
out = [base, f"{base} se", f"{base} si"]
if len(tok.mtag) > 10 and tok.mtag[10] == "N":
    out.append("ne" + base)
úspěch, NNIP1-----N----  ->  ['úspěch', 'úspěch se', 'úspěch si', 'neúspěch']
cenit_:T, VpMP---XR-AA---  ->  ['cenit', 'cenit se', 'cenit si']

3 · Bridge and load_bridge(): everything loaded once

pdt_frequencies.py:86–116

A Bridge holds the annotation wordnet, the tag index, the CILI map, wncze 2.2, and, for every ILI, the senses of its release synset keyed by lemma. That last dictionary makes the final test a lookup.

words = {ili: {s.word().lemma(): s for s in ss.senses()} for ili, ss in cs.by_ili.items()}
return Bridge(nas, tag_index(nas), pwn15_ili(), cs, words)

4 · fate(): the decision chain

pdt_frequencies.py:119–152

Ten early returns, one per fate, in the order of the diagram above. The tag is looked up through tag_key(), which drops the leading zeros of an offset as the index does. Each returns a Fate carrying as much as the word got: the annotation synset, then the ILI, then the sense. The same function decides the words for the validation sheets, so the counts and the sheets cannot disagree.

syn = b.nas.get(b.index.get(tag_key(tok.tag), ""))
...
if hit[1] < MIN_CONFIDENCE:
    return Fate("CILI link below confidence 1", syn, hit[0])
senses = b.words.get(hit[0])
if senses is None:
    return Fate("concept not in wncze", syn, hit[0])
lemma = next((c for c in candidates(tok) if c in senses), None)

5 · main(): count, keep the residue, check negation

pdt_frequencies.py:169–230

For every token it tallies the fate, and keeps four counters keyed by what a maintainer would act on: counted senses, missing words, new synsets and exceptions. It also counts, for each kind of tag, how many words are negated: 99.7% of words with exception 4 are, against 0.7% of words tagged with a synset, which is how exception 4 was identified as "missing negative sense".

negated[kind] += tok.mtag[10:11] == "N"
f = fate(tok, b)
fates[f.label] += 1

6 · write_records(): change records for czech-wn

pdt_frequencies.py:267–283

Each count becomes a set_count line in the format of the czech-wn change log, naming the corpus, source and reason. The ids are provisional; the maintainer numbers them into the log.

{"id": "wncze-2.2-pdt-4295", "action": "set_count", "lexicon": "wncze",
 "synset": "wncze-05903215-n", "lemma": "slovo", "new": "39", "corpus": "PDT", ...}

The result: counts for 7,080 senses, from 86.5% of the 102,696 words tagged with a synset. 414 of those senses already have an NTU-MC count.

How much to trust this

This page was written by an AI from the source file, and checked by explainer_check.py for identifiers, line references and links. Treat the code as the source of truth:

  • Every code claim carries a file:line reference: open it.
  • The numbers come from one run on 2026-11-16, recorded in report/facts-freq.json, and move when the data does.
  • The example words were found by running fate() over read_tokens() and keeping the first word with each fate.
  • Writing this page found a bug, since fixed (commit df27b6f). Most tags drop the offset's leading zeros (1307561), and the tag index is keyed that way, but four tags keep them (00600945 for poskytnout, dát, dávat, udělit, and three more). Their 55 words failed the lookup and were reported as tag names no synset. tag_key() in pdt_sources.py now strips the zeros before the lookup. Of the 55 words, 18 are now counted and 37 are words missing from their wncze synset: counted 88,836 → 88,854, senses 7,079 → 7,080.
  • The quiz answers follow from the code; where one disagrees, the code wins.

Glossary

tagwhat the annotation gives a word: a synset id without zeros (1307561), an id of a new synset (NAS-450034833), an exception code, or -.
annotation wordnetCzech WordNet 1.9 PDT, the copy of the wordnet the annotators chose from; its ids are WordNet 1.5 offsets.
ILIan Interlingual Index id (i69544), one per concept across wordnets; the key that joins the two Czech wordnets.
confidencehow sure the CILI 1.5 map is of a link, from 0 to 1; only links of 1 are used.
sensea lemma in a synset; what a count is attached to.
change recordone JSON line of the czech-wn log that changes the wordnet, with its user, source and reason.
exceptiona tag saying no synset fits: missing sense, proper name, missing negative sense, and so on.
