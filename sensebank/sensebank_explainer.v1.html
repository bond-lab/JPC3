Background

The Prague Dependency Treebank (PDT) is sense-annotated: words are tagged with wordnet synsets. But those tags were made against Princeton WordNet 1.5, an inventory decades out of date. Synsets have since been split, merged, renumbered, and dropped. Project 3 re-anchors the tags to the current Czech wordnet — and, more interesting, characterises the residue that will not carry over.

Why the numbers moved

A synset offset is just a byte position in a data file, so every release renumbers everything. The same concept has a different number in 1.5 and in 3.0 — and the Czech wordnet's synset ids are 3.0 offsets, so a 1.5 tag cannot be looked up directly. Four concepts, both numbers:

The script's own docstring example shows the trap: 00007846-n is person in 3.0, but as a 1.5 offset it is nothing — the table has no such row, and the script answers NO-ILI. The 1.5 offset for person is 00004865-n. Another trap: the POS suffix is part of the key. 00002403-a is able, but 00002403-n is entity (i35545) — the same number in two different data files.

The CILI table

The feared route is a chain of version maps (1.5 → 1.6 → … → 3.0). It is unnecessary. The CILI project keeps historical tables under older-wn-mappings/, including ili-map-pwn15.tab, which maps a 1.5 offset straight to an ILI. And the Czech wordnet is keyed to ILIs. The file is 1.8 MB of tab-separated lines; the first three and the last one:

i1	00002403-a	1
i2	00002738-a	1
i3	00002958-a	1
…
i117639	09185830-n	1

91,349 rows, 90,030 distinct offsets, 87,600 distinct ILIs, and (in the copy fetched 2026-11-04) no comment lines at all — the # guard in the parser is defensive. The rows are not one-to-one in either direction:

  • Splits — 943 offsets map to more than one ILI (742 to two, 114 to three, 49 to four, one to ten). 00007165-a connected maps to four ILIs at confidence 0.25 each: joined or linked together (i3157, Czech spojený), plugged in (i9046), related by kinship (i10801, příbuzný) and wired to an alarm system (i14259).
  • Merges — 3,284 ILIs are reached from more than one 1.5 offset. Both 01422174-n and 01422297-n are dog (i46360); person gets 00004865-n at confidence 1 and 06148720-n at 0.931.

Three columns. The 1.5 table has ili, offset-pos, and a confidence flag — unlike the two-column 3.1 table. Parse all three; the confidence column is itself worth reporting on: 87,891 rows have confidence 1, and 3,458 rows (on 2,139 distinct offsets) have less — values like 0.5, 0.333, 0.25, 0.999.

Last row wins. pwn15_to_ili() builds a plain dict, so for a split offset only the last ILI survives. For 00007165-a that is i14259 (wired to an alarm), which has no Czech synset — so the script prints MISSING-SYNSET even though spojený exists under i3157. Keeping all candidates (and their confidence) is the first improvement to make.

Intuition

Each PDT tag is a 1.5 offset. Look it up in the table to get an ILI, then ask the Czech wordnet for the synset with that ILI. Every tag lands in one of three buckets. Ten real offsets, with the English synset for the ILI (from omw-en 2.0) so you can see what each one means:

missing-synset is an ILI the table knows but the Czech wordnet has no synset for. It is the common case. Over the whole table (one run, 2026-11-04, ntumc-cs:2026.08):

Counted by concept rather than by offset, 26,373 of the 87,600 ILIs resolve to a Czech synset — so the bridge reaches about 30% of the 1.5 inventory before you touch PDT, and the Czech wordnet is thinnest on adjectives (7% of them). A random handful of what is missing: basivertebral vein, academic costume, lucrative, septation, logical relation, self-awareness, Scandentia (tree shrews), unabridged dictionary, modernity, testily — mostly technical and rare, some everyday (cold as a sensation). Every ILI in the table does have an English synset in omw-en 2.0, which is how the glosses above were found. The unmapped rest is the bug list for the maintainers.

Code

Four parts, in the order they run.

1 · Configuration

pdt_to_czech.py:25–29

Share the wn database under patterns/.wn_data, name the CILI table's URL, and cache a copy beside the script. After one run the cache is sensebank/ili-map-pwn15.tab, 1.8 MB; *.tab is gitignored, so it stays local.

2 · pwn15_to_ili()

pdt_to_czech.py:32–42

Download the table once, then read the cache. Skip comment lines, split each line on tabs into three fields, and build a lookup from offset to ILI.

ili, offset, *_confidence = line.split("\t")   # three columns
out[offset.strip()] = ili.strip()

One line in, one dict entry out — the confidence is read and dropped:

line  = "i1\t00002403-a\t1"
ili, offset, *_confidence = ["i1", "00002403-a", "1"]
out["00002403-a"] = "i1"

91,349 lines become 90,030 keys, because a split offset is assigned several times and keeps only its last ILI (00007165-a → i14259, not i3157).

3 · lookup()

pdt_to_czech.py:45–50

One offset in; its ILI and the Czech lemmas out. No ILI means the tag is not in the 1.5 table; an ILI with no lemmas means the Czech wordnet lacks it.

ili = mapping.get(offset)
if not ili:
    return None, []
return ili, [w.lemma() for s in cs.synsets(ili=ili) for w in s.words()]

The three outcomes, one real call each. Note that the Czech synset found by ILI is ntumc-cs-00007846-n: its id is the 3.0 offset, which is why the 1.5 number could not have been used directly.

lookup("00004865-n", mapping, cs)
  -> ("i35562", ["smrtelník", "člověk", "duše", "osoba", "jednotlivec", "někdo"])
     cs.synsets(ili="i35562") == [ntumc-cs-00007846-n]

lookup("00002958-a", mapping, cs)      # abaxial, dorsal
  -> ("i3", [])                        # ILI known, no Czech synset

lookup("00007846-n", mapping, cs)      # a 3.0 offset, not in the 1.5 table
  -> (None, [])

4 · main()

pdt_to_czech.py:53–70

Take offsets as arguments or one per line on stdin, classify each as mapped / missing-synset / no-ili, print a line per tag, and the counts to stderr. Feed it the real PDT tags and the counts become your first result. The ten offsets from the Intuition table, one per line in tags.txt, give this (stdout, then the stderr line):
