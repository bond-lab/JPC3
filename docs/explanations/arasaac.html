Background

ARASAAC is a large open set of pictograms used in augmentative and alternative communication (AAC) — for people who cannot speak, a board of pictures stands in for words. Project 4 links those pictures to Czech wordnet synsets so that each concept has an image, and, through the wordnet, the same picture can serve every language.

What a pictogram record looks like

ARASAAC has a public API. Searching its Czech index for pes "dog" returns 7 pictograms; for kočka "cat" 6; for běžet "run" 4; for učitel "teacher" 64; for dům "house" 151. Each hit is a JSON object. Here is the first one for pes, trimmed to the fields that matter (queried 2026-11-04):

    {"keyword": "fena", "plural": "feny", "type": 2, "hasLocution": false}

                 "domestic animal", "core vocabulary-living being"],
  "tags": ["animal", "carnivorous", "vertebrate", "mammal", "viviparous", ...],
  "created": "2009-01-19T13:23:19.000Z", "lastUpdated": "2023-11-04T14:29:52.636Z"

The script uses exactly two of these fields: _id (the pictogram number, also the name of its image file) and synsets. The keywords are what the search matched on — note that fena "bitch" is a keyword of the same picture — and the sex, skin and hair flags say whether gendered or skin-tone variants exist. The search is a keyword match, so it casts wide: pes also returns four therapy-dog pictograms whose keyword is asistenční pes "assistance dog"; and červený "red" returns no colour at all, only Červený kříž "Red Cross" and Červený půlměsíc "Red Crescent" (two pictograms each), a red-nose costume, hematoidní křemen "red quartz" and two fish (cejn červený, červený štír).

Three kinds of synset id

The lucky part: ARASAAC pictograms already carry a WordNet 3.1 synset id in their metadata — 02086723-n for the dog above. So there is nothing to guess — only a version gap to cross. The Czech wordnet (ntumc-cs) is an expand wordnet keyed to Princeton WordNet 3.0 offsets, and between 3.0 and 3.1 most offsets changed:

Concept3.1 id (ARASAAC)3.0 id (the Czech synset)ILI
dog02086723-nntumc-cs-02084071-ni46360
cat02124272-nntumc-cs-02121620-ni46593
teacher10713754-nntumc-cs-10694258-ni93557

Asking the Czech wordnet for ntumc-cs-02086723-n raises an error — there is no such synset. What the two versions share is the Collaborative Interlingual Index (ILI): a stable concept id. CILI publishes a table from 3.1 offsets to ILIs, ili-map-pwn31.tab, 117,587 tab-separated lines with no header, starting:

i1	00001740-a
i2	00002098-a
i3	00002312-a
i4	00002527-a
i5	00002730-a

It covers 82,064 nouns, 13,757 verbs, 10,654 satellite adjectives (-s), 7,459 adjectives and 3,605 adverbs. Turn the table round (02086723-n → i46360), ask the Czech wordnet for ILI i46360, and you get ntumc-cs-02084071-n with the lemmas psovitá šelma, pes. That is the whole bridge — the same one project 5 crosses from Wikidata.

Why precision matters here. A wrong synset tag means the wrong picture, and a child who cannot speak is handed the wrong word. Of the six projects this is the one where a lexical slip reaches a real user fastest.

Intuition

Search ARASAAC for a Czech word, read each pictogram's synset tag, convert it to an ILI, and look up the Czech synset. A pictogram can carry more than one tag, and the cat pictograms all carry two. Pictogram 7114 follows both:

The first tag lands on kočka; the second is the informal English kitty, puss, pussycat ("informal terms referring to a domestic cat"), a sense the Czech wordnet has no synset for. Both are honest results. Here are real rows from several searches, decided by hand:

Three drawings of a dog (7202, 2517, 38967) resolve to the same Czech synset — exactly what you want. Each line also carries the image URL, so the next step (attach it, check it is a fair picture of that sense) can start at once: 7202, 7114, 6556. A tag that yields no Czech synset prints MISSING: a concept the Czech wordnet lacks (kitty, detached house, assistant professor, domicile all turned up in a handful of searches), or a wrong tag to report back to ARASAAC. A pictogram with no tags at all — Kočka a myš "cat and mouse" (a game), červený nos, inspektor školství, 13 of the 64 učitel hits — prints nothing, and is the other half of the project: matching the untagged ones by keyword.

2 · load_cili()

arasaac_to_czech.py:31–40

Download the 3.1 table once (2.1 MB, cached beside the script as ili-map-pwn31.tab) and invert it into an offset → ILI dictionary. Each line is ili<TAB>offset; the script splits on the first tab and stores it the other way round:

for line in CILI_TAB.read_text(encoding="utf-8").splitlines():
    if "\t" in line:
        ili, pwn = line.split("\t", 1)
        mapping[pwn.strip()] = ili.strip()
line     = "i46360\t02086723-n"
ili, pwn = "i46360", "02086723-n"
mapping["02086723-n"] = "i46360"        # 117,539 keys from 117,587 lines

The if "\t" in line guard skips blank lines (the file has no header). The two counts differ because 47 offsets are listed under two ILIs (one under three) — 00493366-s under both i118 and i2763, 00472688-n under i37881 and i37882 — and a dictionary keeps whichever came last. Twelve of the 47 are nouns; none of the 37 tags met in the searches for this page is among them. The same function is in the Wikidata script; the bridge is shared.

3 · search()

arasaac_to_czech.py:43–47

One HTTP call to ARASAAC's Czech search; raise_for_status() turns a failed request into an error instead of an empty list. The result is the JSON list from the Background section, one dictionary per pictogram:

search("pes")     → 7 dicts; [p["_id"] for p in ...] = [7202, 2517, 38967, 36181, 35997, 29202, 29203]
search("kočka")   → 6 dicts; the last, 36647, has "synsets": []
search("učitel")  → 64 dicts; 6556 has "synsets": ["10713754-n", "10579780-n", "10500315-n"]

4 · main()

arasaac_to_czech.py:50–62

For each of the first N pictograms (default 5 — so pes shows 7202 to 35997 and drops 29202 and 29203), and each synset tag it carries, resolve the ILI, collect the Czech lemmas, and print one tab-separated line with the image URL at the end.

for off in picto.get("synsets", []):             # e.g. '02086723-n'
    ili = pwn31_to_ili.get(off)
    lemmas = [w.lemma() for s in (cs.synsets(ili=ili) if ili else []) for w in s.words()]
    print(f"{pid}\t{off}\t{ili or '-'}\t{'|'.join(lemmas) or 'MISSING'}\t{IMAGE.format(pid=pid)}")

The three paths through that loop, on real pictograms:

7202   off="02086723-n"  ili="i46360"  cs.synsets → [ntumc-cs-02084071-n]  lemmas=["psovitá šelma","pes"]  → "psovitá šelma|pes"
35997  off="05162155-n"  ili="i64071"  cs.synsets → []                      lemmas=[]                       → "MISSING"
36647  synsets=[]        (loop body never runs: nothing is printed)

Because N counts pictograms, not lines, kočka 2 prints four lines — two tags for each of two pictograms — and the two MISSING lines there are the kitty sense, not a failure. The ili or '-' branch (a 3.1 offset absent from the CILI table) did not occur in any search tried for this page. The wn object is opened once, before the loop, so the database is not reopened per pictogram. The output of two runs (2026-11-04):
