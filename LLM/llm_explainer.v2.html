Background

Project 6 asks a language model to flag suspicious synsets — a lemma in the wrong sense, a missing synonym, a spurious member — with a rationale, and then measures how good those flags are. A model will happily flag things; the question is whether it is right.

The pieces: synset, lemma, ILI, gloss

A synset is one concept with the words that name it. The Czech synset wncze-02686317-n holds three lemmas, propisovací tužka, propiska, kuličkové pero. Its ILI (interlingual index) is i50413, and the English synset with the same ILI, omw-en-02783161-n, holds ballpoint, ballpoint pen, ballpen, Biro with the gloss "a pen that has a small metal ball as the point of transfer of ink to paper". The ILI is what lets the script get from the Czech side to the English side without looking at any word. The two ids are no help: the numbers in them are offsets in different Princeton WordNet versions. A few more:

wncze-09908715-ni93005 pěvec, zpěváksinger, vocalist, vocalizer, vocaliser a person who sings

One thing the table hides: the Czech wordnet has few glosses of its own. Of its 21,144 noun synsets, 881 carry a definition (934 of all 28,977 synsets), and the script does not read them. So the gloss a model reads is always the English one, reached through the ILI. That is why this script opens both wncze:2.2 and omw-en:2.0.

Two decisions

Two decisions make the answers measurable, and this script makes both. First, ground the model: instead of letting it free-associate about a Czech word, hand it evidence for the same concept — the English lemmas and gloss reached through the shared ILI in omw-en, and, where the Wikidata run found one, Wikidata's Czech label. Second, fix the output shape: a closed verdict, a closed problem type, one sentence of rationale, a confidence. Prose answers cannot be scored; a schema can.

What the Wikidata label looks like

Project 5's wikidata_to_czech.py writes a TSV with the columns kind qid wn31 ili wikidata_cs czech_lemmas. There was no such file on disk when this page was built, so every record in the run below has "wikidata_cs": null. To see the other branch, one row was written by hand from a live Wikidata lookup (2026-11-04): item Q160137 ballpoint pen has the Czech label propiska and the ILI property P5063 = i50413 — the same ILI as the propiska synset above.

present	Q160137	02786184-n	i50413	propiska	propisovací tužka|propiska|kuličkové pero

With that one-row file, the record for the propiska synset gains "wikidata_cs": "propiska". That synset is not among the 200 that seed 1 draws from release 2.2, so a run with the file as the third argument still reports 0 with a Wikidata label: a label only shows up for a synset that is sampled. Note that the label agrees with one Czech lemma but not with the others — this is the kind of independent evidence the model is meant to cite.

The problem types, with faces

The schema's problem field has five values. Here is what each looks like in the wordnet, as a reader's first impression — the gold label is the project's job, not this page's:

problema real record that fitswhy
wrong-sense i110701 postavení ↔ erection, hard-on "an erect penis" postavení is "position, standing" or "the act of erecting" — and it already sits, correctly, in i40197 erecting, erection. The sexual sense of the same English word was translated as if it were the same thing.
missing-lemma i85697 váha ↔ Libra "a small faint zodiacal constellation" The Czech name of the constellation is Váhy (plural); it is not in the wordnet at all. váha "weight, scales" is in three other synsets (scale and two senses of weight) where it belongs — so this is also arguably wrong-sense. The taxonomy is not always clean, which is why two annotators and a κ are in the brief.
spurious-lemma i91861 osadník, farník ↔ parishioner "a member of a parish" farník is right. osadník is "settler, colonist" and is correctly in i92895 settler, colonist too; here it is an extra member that does not belong.
bad-gloss i94197 ubožák ↔ wretch "performs some wicked deed"; i59030 raketa ↔ skyrocket, rocket "sends a firework display high into the sky" Both glosses are verb phrases inherited from Princeton WordNet, not definitions of a noun; and ubožák is a pitiable wretch, not a wicked one. The evidence itself can be the problem.
none i91691 porodník ↔ obstetrician, accoucheur Lemma, English lemmas and gloss all point at the same concept. Most of the 200 look like this.

No API call here. This is the half you can run offline and read with your own eyes before spending a token. The call itself — and the validation of what comes back against a human gold standard — is the project.

Notice what the evidence does for you in these rows. For postavení the gloss alone settles it. For osadník you need to know Czech, or to see that the same lemma sits in settler, colonist — which the record does not contain. That is a design choice worth questioning in the project: should the evidence also list the other synsets a lemma belongs to?

The answer, same shape every time

And the answer the model must return:

{"synset": "...", "verdict": "ok | suspect",
 "problem": "wrong-sense | missing-lemma | spurious-lemma | bad-gloss | none",
 "rationale": "one sentence, citing the evidence", "confidence": 0.0}

Filled in for the postavení record it might look like this. This is a hand-written illustration of the schema, not the output of any model — the script makes no API call:

{"synset": "wncze-13237963-n", "verdict": "suspect", "problem": "wrong-sense",
 "rationale": "'postavení' means position or the act of erecting; the gloss 'an erect penis' and lemma 'hard-on' are a different sense of 'erection'.",
 "confidence": 0.9}

With the shape fixed, the evaluation is ordinary: a human labels a blind sample with the same schema, and you report precision and recall for suspect, a confusion matrix over problem, and whether confidence tracks correctness. The cleanest experiment is an ablation — run it with and without the Wikidata field and see whether grounding cuts false flags.

2 · wikidata_labels()

build_evidence.py:40–45

Optionally read the TSV that wikidata_to_czech.py writes and keep one Czech label per ILI. If no file is given, or the path does not exist, the result is an empty dict and the Wikidata field is simply null — which is what the ablation compares against.

return {row["ili"]: row["wikidata_cs"] for row in csv.DictReader(fh, delimiter="\t") if row["ili"]}

Real calls and what they return (the one-row TSV is the hand-written one from the Background):

wikidata_labels(Path("candidates_1row.tsv"))  →  {'i50413': 'propiska'}
wikidata_labels(None)                         →  {}
wikidata_labels(Path("/nonexistent.tsv"))     →  {}

The if row["ili"] matters: the project-5 TSV also contains rows of kind no-ili whose ili column is empty, and without the filter they would all collapse onto the key "".

3 · evidence()

build_evidence.py:48–58

For one Czech synset, follow its ILI to the English synset and collect the lemmas and the first gloss; add the Wikidata label if any. The ILI is the only join key — no string matching.

en_syn = en.synsets(ili=ss.ili) if ss.ili else []
"english_lemmas": [w.lemma() for s in en_syn for w in s.words()],
"gloss": next((d for s in en_syn for d in s.definitions()), None),

Traced for the propiska synset:

ss.id                         →  'wncze-02686317-n'
ss.ili                        →  'i50413'
[w.lemma() for w in ss.words()]
                              →  ['propisovací tužka', 'propiska', 'kuličkové pero']
en.synsets(ili='i50413')      →  [omw-en-02783161-n]
english_lemmas                →  ['ballpoint', 'ballpoint pen', 'ballpen', 'Biro']
gloss                         →  'a pen that has a small metal ball as the point of transfer of ink to paper'
labels.get('i50413')          →  None        (no TSV)   /   'propiska'  (one-row TSV)

The next(…, None) on line 56 is written for the general case — several English synsets, several definitions each — and returns the first definition of the first synset, or None if there is nothing. In this data the general case never arises: every one of the 20,840 ILIs resolves to exactly one omw-en synset, and every omw-en noun synset has exactly one definition (0 have more, 0 have none). So in the run, gloss is never null and never a second-best choice. To see the fallback you have to feed it something else:

next((d for s in [] for d in s.definitions()), None)                       →  None
next((d for s in [S(['first gloss','second gloss']), S(['third gloss'])]
          for d in s.definitions()), None)                                →  'first gloss'
   (S is a two-line stand-in class with a definitions() method — a toy, not wordnet data)

4 · main()

build_evidence.py:61–76

Seed the random generator so the sample is reproducible, draw N noun synsets that have an ILI, write one JSON line per synset, and print the schema. Czech is preserved with ensure_ascii=False.

random.seed(1)                                   # a reproducible sample
sample = random.sample([s for s in cs.synsets(pos="n") if s.ili], n)

What is being sampled? Every Czech noun synset that has an ILI. The filter on line 71 removes very little, but what it removes is interesting:

So the model will never be asked about Čech or prales: with no ILI there is no English evidence to show it. Those 304 are exactly the synsets that need a different kind of check (a Czech-only one), which is worth saying in the report.

With random.seed(1) the first five of the 200 are always wncze-02902747-n, wncze-13318208-n, wncze-01046774-n, wncze-04711682-n and wncze-02686723-n (kasule, spalničky, obchod, ocelová modř, skotská čapka).
